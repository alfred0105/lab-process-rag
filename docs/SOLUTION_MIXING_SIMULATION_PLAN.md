# 실제 수용액 혼합 시뮬레이션: 모델 범위와 적용 계획

작성일: 2026-10-29

## 요약

교반 중인 용액은 단일한 “혼합 계산”으로 충분히 설명되지 않는다. 용기 안의 거시 유동, 공급액이 퍼지는 중간 규모 혼합, 분자 확산, 산·염기 및 금속 착물 평형, 과포화, 핵생성·성장·응집은 서로 다른 물리·화학 과정이며 시간 척도도 다르다. 따라서 Lab Process RAG에서는 각 단계를 독립 모델로 취급하고, 실제 공정 기록과 모델 입력이 확인된 범위에서만 단계별 결과를 다음 계산에 전달해야 한다.

현재 PHREEQC는 용액 조성·조건에 따른 열역학적 종분포 및 포화도 계산에 사용한다. 이를 대체하지 않는다. 다만 PHREEQC 입력을 균일 벌크 용액 하나로 주는 것만으로는 임펠러 주변의 국소 농도와 온도 차이를 재현할 수 없다.

## 실제 혼합에서 일어나는 일

1. **거시 혼합(macromixing)**: 임펠러가 용기 전체를 순환시킨다. 상하 순환, 벽·바닥의 정체 영역, 와류, 임펠러 뒤의 전단 영역은 용기와 교반기 형상에 따라 달라진다.
2. **중간 규모 혼합(mesomixing)**: 새로 투입한 시약의 큰 농도 덩어리가 주변 액체에 끌려 퍼지고 작아진다. 주입 위치, 노즐 크기, 투입 속도, 주입 시점이 영향을 준다.
3. **미세 혼합(micromixing)**: 작은 농도 덩어리 안에서 난류 변형과 분자 확산이 조성 차이를 줄인다. 반응·핵생성이 이보다 빠르면 전체 평균 조성은 같아도 주입점 근처에서 먼저 다른 상이 생길 수 있다.
4. **용액 반응**: 산·염기, 가수분해, 착물화, 산화환원, 용해/침전 평형이 조성을 바꾼다. pH와 활동도는 농도뿐 아니라 온도와 이온강도에 좌우된다.
5. **고체 생성**: 과포화가 생겨도 침전이 즉시 확정되는 것은 아니다. 유도 시간과 핵생성 장벽이 있고, 이후 결정 성장·응집·파쇄·재용해가 입도 분포와 수율에 영향을 준다. 기판에서 자라는 이종 핵생성은 벌크 입자 침전과 다른 경로다.

침전 모델에서는 혼합 시간과 핵생성 시간의 비가 중요하다. 문헌은 거시·중간·미세 혼합, 반응, 핵생성·성장, 응집·파쇄를 별도 하위 과정으로 다룬다. [KONA의 침전 공정 혼합·유체역학 리뷰](https://www.jstage.jst.go.jp/article/kona/33/0/33_2016021/_html/-char/en), [RSC의 반응/반용매 결정화 혼합 모델 리뷰](https://pubs.rsc.org/en/content/articlelanding/2021/re/d0re00223b), [결정화 핵생성·성장과 혼합 시간 척도](https://books.rsc.org/books/edited-volume/1895/chapter/2487976/Nucleation-and-Crystal-Growth-in-Continuous)

## ZnO–질산아연–HMTA에 특히 주의할 점

이 계는 “RPM을 올리면 ZnO가 더 잘 섞인다”는 일반 규칙으로 단정할 수 없다. HMTA 가수분해와 pH 변화, Zn(II) 가수분해·착물화, Zn(OH)₂ 중간상, 기판 표면의 성장, 용액 내 입자 생성이 조건에 따라 경쟁한다. HMTA를 이용한 수열 ZnO 성장의 상세 반응은 연구 문헌에서도 완전히 확정되지 않았다고 보고된다. [Scientific Reports의 수열 ZnO 성장 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC5680254/)

아연염의 반대 이온도 경로에 영향을 준다. 질산염 조건에서는 용기와 pH 전극처럼 액체에 잠긴 표면에서 생성물이 자라는 경향이, 아세테이트 조건에서는 용액 분산 상태 생성이 더 선호된 실험 결과가 보고되었다. 따라서 수용액 전체를 균일한 벌크 침전으로 가정하는 모델은 seeded hydrothermal ZnO의 표면 성장까지 설명하지 못한다. [RSC의 HMTA-ZnO 반대 이온 연구](https://pubs.rsc.org/en/content/articlehtml/2020/ce/d0ce00847h)

질산아연·HMTA 농도, 질산 이온에 따른 pH 변화, 성장 형태 사이의 관계도 실험적으로 다뤄졌다. [ACS Crystal Growth & Design 연구](https://pubs.acs.org/doi/10.1021/acs.cgd.3c00068)

## 시스템에 넣을 모델과 역할

| 단계 | 후보 오픈소스 | 계산할 것 | 주요 입력 | 결과를 해석할 때의 한계 |
|---|---|---|---|---|
| 교반조 유동과 공급액 분포 | **OpenFOAM**의 유동 solver + scalar transport / `twoLiquidMixingFoam` 계열 사례 | 속도장, 순환·정체영역, 공급액의 공간별 농도, 혼합 시간 근사 | 용기와 임펠러 형상·치수·위치, 배플, 충전 높이, 회전 방식/RPM, 유량·주입 위치/속도, 밀도·점도·확산계수 | 메시, 난류/회전 모델, 경계조건 및 검증이 필요하다. 계산된 농도장은 화학 반응이나 침전을 자동으로 뜻하지 않는다. OpenFOAM은 단일 유체 scalar transport와 두 유체 혼합 solver를 제공한다. [solver 목록](https://www.openfoam.com/documentation/user-guide/a-reference/a.1-standard-solvers), [scalar transport 문서](https://doc.openfoam.com/2312/tools/processing/solvers/rtm/basic/scalarTransportFoam/) |
| 벌크 열역학 | **PHREEQC** (현재 연결) | 용액 종분포, 선택한 고체상 포화지수 | 투입 총량, pH, 온도, 데이터베이스 | 포화는 실제 핵생성/침전의 증거가 아니다. pH·총량·전하 균형·DB 선택이 중요하다. |
| 반응속도/용해·침전 kinetics | PHREEQC kinetics 또는 필요 시 Reaktoro | 속도식이 알려진 수용액 종·고체상의 시간 변화 | 검증된 속도식, 속도상수, 표면적, 활성화에너지 등 | 해당 화학계의 검증된 속도식이 없으면 예측값을 만들 수 없다. 열역학 평형과 속도론은 별도다. |
| 입자 크기 분포 | population balance (예: CADET-Core가 제공하는 결정화/PBM 기능 또는 검증된 별도 구현) | 핵생성·성장·응집·파쇄에 따른 입도 분포 | 핵생성/성장 속도식, 응집·파쇄 kernel, 초기 씨앗 분포 | CFD와 자동 연계되어 있지 않다. CADET의 결정화 모델도 이러한 속도 모델이 있어야 하며, 임펠러 CFD를 대체하지 않는다. [CADET 결정화 모델](https://cadet.github.io/master/modelling/crystallization/index.html) |
| 기판 표면 성장 | 계면 반응/확산 모델을 별도 정의 | 기판 표면에서의 성장 플럭스와 공간별 두께/길이 경향 | 기판 재료·면적·방향, 표면 상태, 흡착/성장 속도식, 경계층 수송 | 벌크 침전 PBM 결과만으로 나노와이어 길이·형태를 말할 수 없다. SEM/AFM/XRD와 같은 실측 결과로 계별 보정이 필요하다. |

## 현재 프로젝트에 적용한 변경

- 시뮬레이션 화면에 **용기 유동 → 시약 혼합 → 수용액 화학 → 침전·성장** 4단계 흐름을 표시한다.
- 선택한 비데모 실험 기록의 기존 공정 조건을 읽고, 혼합 해석에 필요한 입력 그룹(교반 속도, 액체 부피, 용기·임펠러 구조, 액체 물성, 투입 순서·속도)이 기록에 있는지 표시한다.
- 이 상태 표시는 입력 준비 상태를 보여줄 뿐이며, 혼합 시간·침전·성장 값을 계산했다고 주장하지 않는다. 값이 기록되지 않았으면 추정하지 않는다.
- PHREEQC를 별도 화학 엔진으로 표시하고, OpenFOAM 유동과 아직 자동 연결되지 않은 상태를 명확히 한다.
- 실험 사용자가 별도 시뮬레이션 설정 폼에 같은 값을 다시 입력하지 않도록, 원칙적으로 공정 기록에 저장된 값을 읽는다. 반복해서 필요한 용기/임펠러 정보는 실험마다 반복 입력하지 않고 방법 또는 재사용 가능한 장비 프로필에 한 번 등록하는 설계를 권장한다. 장비 프로필 기능은 아직 구현되지 않았다.
- `GET /api/experiments/{id}/simulations/openfoam-plan`은 저장된 비데모 공정 기록을 OpenFOAM 14의 `incompressibleFluid/simpleRushtonMRF` 사례에 대조해 SI 입력 후보, 누락 조건, 형상 호환 여부를 표시한다. 여기서 `ready_for_review`는 입력 계약을 만족한다는 뜻이며 CFD 실행 완료를 뜻하지 않는다. 이 계획 API는 아직 메쉬 생성, solver 실행, 계산 결과 저장을 수행하지 않는다.

## 입력을 간결하게 유지하면서 필요한 정보 확보하기

### 실험별로 공정 기록에 남길 값

- 용액 총량 또는 부피, 각 시약의 농도·투입량
- 투입 순서 및 연속/일괄 투입 여부, 투입 시간 또는 유량
- 혼합 속도와 혼합 유지 시간
- 반응 온도 및 실제 pH 측정값(있는 경우)
- 혼합 중 관찰/측정: 색, 탁도, pH 변화, 온도 등

### 방법/장비 프로필에 한 번 저장할 값

- 용기 형태·내경·바닥 형상, 배플 유무, 운전 액면 높이
- 임펠러 종류·직경·날개 수·높이·방향
- 주입구 위치/방향
- 용액 밀도·점도·확산계수(측정/문헌/모델 추정 등 출처를 표시)

직접 측정하지 않은 물성은 문헌/모델에서 온 값임을 표시하고, 출처와 온도를 함께 보존해야 한다. 일반 사용자는 세부 모델 파라미터를 매번 입력하지 않으며, 기록된 공정값과 저장된 방법/장비 설정으로 계산을 시작하는 것이 목표다.

## 이 Mac에서의 실행 가능성

현재 개발 환경은 Apple Silicon MacBook Air M5, 24 GB RAM이다. OpenFOAM Foundation이 안내하는 Apple Silicon용 ARM Ubuntu 경로(Multipass)를 사용해 OpenFOAM 14를 설치했다. VM에는 6 vCPU, 8 GB RAM, 60 GB 가상 디스크를 할당했다. 공식 예제 `incompressibleFluid/pitzDailySteady`의 메시 생성과 정상유동 계산을 실행했고, solver는 287회 반복 후 수렴해 `End`까지 완료했다. 이는 설치/일반 solver 동작 검증이지 교반조 혼합 검증은 아니다. [OpenFOAM macOS 설치 안내](https://openfoam.org/download/14-macos/), [OpenFOAM 14 Ubuntu 패키지 안내](https://openfoam.org/download/14-ubuntu/)

**현재 앱은 실제 혼합 CFD를 아직 실행하지 않는다.** OpenFOAM은 VM에서 실행 가능하지만, UI/API와 연결하는 mixer case는 없다. 정밀 메시, 다상·자유표면, 복잡한 임펠러 회전 및 반응 연계가 24 GB 노트북에서 실용적이라고 보장할 수 없다. 작은 메시와 짧은 시간 구간부터 시작하고 계산 자원과 실험 관측값으로 범위를 정해야 한다.

설치 확인에 쓴 `mixerVessel2DMRF` 튜토리얼은 현재 사용자 공정 계산의 템플릿으로 바로 쓰지 않는다. 제공된 block mesh는 `rVessel=0.1 m`, `rRotorTip=0.05 m` 등의 고정된 2차원 로터·스테이터 단면을 사용하고, 예제 phase 설정에는 물·기름·수은·공기가 들어 있다. 이를 일반 교반 용기의 형상이나 실제 시약 조성으로 간주하면 안 된다. 현 입력 준비 점검은 부피·RPM·밀도·점도 단위와 용기 지름/높이 및 임펠러 종류/지름의 구체성을 확인하지만, 이 점검 통과만으로 CFD가 호환되거나 실행 가능하다는 뜻은 아니다.

## 다음 구현 순서

1. **측정 가능한 기준 사례 확보**: 실제 용기/임펠러 치수, 투입량·순서·속도, 점도/밀도, 교반 RPM, 온도, 혼합 시간 및 pH/탁도 시간 기록을 포함한 한 공정 사례를 선택한다.
2. **방법 장비 프로필 구현**: 용기·임펠러 형상을 실험마다 반복 입력하지 않게 한다. 단위/출처 검증을 포함한다.
3. **OpenFOAM 최소 사례**: 일반 정상유동 및 패키지 교반기 tutorial의 설치 확인까지 완료. 설치 확인용 예제와 사용자 실험을 분리한 뒤, 저장된 장비 치수를 반영하는 단일 액상 탱크와 tracer/scalar 방출 사례를 만든다. 사용 전 질량 보존, 메시·시간 간격 민감도, 측정 혼합 시간과 비교한다.
4. **실험과 비교**: tracer 혼합 시간 또는 pH/전도도 probe 시간 응답과 CFD를 대조한다. 기준 사례 없이 RPM만으로 보정하지 않는다.
5. **PHREEQC와 연결**: CFD 격자 전체의 복잡한 반응을 바로 풀기보다, 먼저 유동 계산에서 뽑은 대표 구역 농도/온도 기록을 PHREEQC 입력 후보로 전달하고 가정을 드러낸다.
6. **반응 kinetics와 표면 성장**: 해당 조성에 대한 속도식과 실험 검증이 확보될 때 추가한다. 이후 PBM으로 입자 크기 분포를 확장한다.

**현재 연결 상태 (2026-10-29)**: 실제 기록의 조건 점검, 지원 형상 차단, OpenFOAM 14 실행 API, 별도 `simulation_runs` 저장, 계산 상태 조회, solver 로그와 시간별 동력 항목 그래프가 연결되어 있다. 완료된 계산 결과는 연구 주제 통합 분석에서 측정 분석과 구분된 입력으로 Gemma에 전달되고, `SIMULATION_OUTPUT` 주장은 해당 시뮬레이션 실행 ID를 요구한다. 데모 실험은 통합 분석에서 제외되며, 문헌 `reference` 기록은 LAB_PATTERN 성과 사례로 오인되지 않도록 차단한다. 공식 simpleRushtonMRF 튜토리얼 사본을 20 s까지 실행해 정상 종료와 출력 파싱을 확인했다. 이는 엔진/화면 경로 점검일 뿐 논문 데이터와의 물리 검증은 아니다. 현재 실제·문헌 기록에는 러시턴 임펠러/배플/용액 물성까지 갖춘 적격 기록이 없어, 응용 사례 CFD는 실행하지 않았다.

**완료 기준**: 실제 실험 기록에서 모델 입력 조건을 구성하고, 출처/모델 가정/상태/결과를 HTML에 표시하며, 재현 가능한 소규모 CFD 결과를 동일 조건의 tracer 혼합 시간 또는 probe 응답 등 실제 측정과 비교해 오차와 적용 범위를 보고한 뒤에만 “혼합 시뮬레이션 검증 완료”로 표시한다.

## 분석 중 필요한 값 탐색: Gemma + 출처 도구 + 사용자 확인

이 흐름은 유용하지만, Gemma가 물성의 진위를 스스로 판단하거나 검색 결과를 곧바로 실험값에 덮어쓰게 해서는 안 된다. 역할을 다음처럼 나눈다.

1. **시뮬레이터가 필수 입력을 결정한다.** 각 도구의 입력 스키마/사전 점검기가 `필수`, `선택`, `이번 계산에는 불필요`를 정한다. 예: OpenFOAM의 유동 계산에는 실제 용기/임펠러 형상과 교반 조건이 필요하다. Gemma가 이 물리적 필수 여부를 임의로 바꾸지 않는다.
2. **Gemma가 누락 항목을 설명하고 검색 계획을 만든다.** 어떤 값이 왜 필요한지, 시료 자체의 실측값인지, 상용 시약의 일반 물성인지 구분하고 알맞은 검색 경로를 제안한다.
3. **허용목록의 데이터 제공처만 호출한다.** 시약 식별/일반 물성은 PubChem PUG REST·PUG View, 적합한 열화학/열물성은 NIST Chemistry WebBook, 논문 메타데이터는 Crossref와 이미 연결된 논문 색인을 사용한다. PubChem에는 제3자 제출 정보도 있으므로 각 값의 원 출처·조건을 보존한다. NIST도 모든 물질·물성에 자료가 있는 것은 아니다. Crossref는 서지 메타데이터 서비스이므로 논문 결과 본문이나 물성의 검증 출처로 간주하지 않는다. [PubChem PUG REST](https://pubchem.ncbi.nlm.nih.gov/docs/pug-rest), [NIST Chemistry WebBook](https://webbook.nist.gov/chemistry/), [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)
4. **출처 값을 시료 lot의 실측값과 섞지 않는다.** 자동 수집 값은 `문헌/공공 DB 참고값`으로 보여주고, 온도·압력·상태·염 형태·수화물·농도 범위와 인용 URL을 붙인다. Lot-specific 순도, 실제 용액 pH, 점도, 시료 질량처럼 사용자/실험에서 결정되는 값은 웹에서 대체할 수 없다.
5. **계산 적용 전에 사용자가 확인한다.** 확인한 공공 기준값은 그 계산에만 사용하거나 프로필에 출처와 날짜를 함께 저장한다. 적용 여부를 확인하지 않은 값은 실행 입력에 들어가지 않는다.
6. **찾지 못한 입력은 빈칸으로 둔다.** 예: “임펠러 지름이 필요합니다. 방법/장비 프로필에서 확인해 입력해 주세요. 모르면 비워두세요.” 사용자가 비워두면 해당 CFD 실행을 막고 어떤 출력이 불가능한지 설명한다. 대체 가능한 도구라면 저정밀 계산으로 자동 전환하지 말고, 사용자가 선택하도록 근거와 한계를 표시한다.

권장 질문 카드에는 `필요한 값`, `왜 필요한지`, `단위와 허용 형식`, `기록/공식 출처에서 찾은 값`, `출처·측정 조건`, `직접 입력`, `모름/미기입`을 둔다. 값 검색은 읽기 전용으로 자동 수행하되, 실험 기록 수정이나 모델 입력 적용은 사용자 확인 뒤에 한다. 원 논문 PDF 접근이 안 되면 Crossref 제목/DOI만으로 내용을 추정하지 않고 “본문 근거 미확보”로 남긴다.
