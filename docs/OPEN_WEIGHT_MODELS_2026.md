# Open-weight LLM landscape for Lab Process RAG

**Research snapshot: 12 October 2026.** This is a survey of major model-producing organizations and their latest official downloadable general-purpose LLM families that can be verified from first-party model cards, repositories, or release pages. It is not a list of every community fine-tune, quantization, or hosted API model. Model families move quickly; check the linked license and model card again before deployment.

## First, a terminology distinction

“Open-source LLM” is often used loosely. The [Open Source Initiative’s Open Source AI Definition](https://opensource.org/ai) describes an AI system as needing more than weights alone; the information needed to study and modify the system matters too. Some vendors publish weights under broadly reusable licenses such as Apache 2.0 or MIT. Others publish downloadable **open weights** under custom terms, acceptable-use policies, or non-commercial licenses. The license column below is therefore a practical deployment flag, not a legal opinion.

## What can comfortably run locally

For a 24 GB Mac, shortlist models whose *quantized weights* do not consume the machine’s whole shared memory. Practical starting bands are roughly 4–8B for generous headroom, 8–14B for a quality/comfort balance, and around 20B only as a carefully bounded experiment. These bands are estimates, not compatibility guarantees; exact quantization, context, runtime and other open apps change the result.

| Trial order | Candidate | Why it belongs in the comparison | Main trade-off |
|---|---|---|---|
| 1 | **Gemma 4 12B** | Current general model, Apache 2.0, multimodal family, plausible fit | Check actual speed and memory with our chosen runtime; vendor ranking claims are not a substitute for our task set. |
| 2 | **gpt-oss-20b** | OpenAI’s local reasoning/tool-use option; explicit MXFP4 memory target | Leaves less headroom; text-only; trained tool ability does not validate citations. |
| 3 | **Ministral 3 8B or 14B** | Apache 2.0, local/edge family, reasoning variants | Measure Korean scientific phrasing and citation behavior. |
| 4 | **Phi-4-Reasoning(-Vision)-15B** | Compact STEM/reasoning plus optional image input | Match the exact vision/text variant and its license; verify Korean. |
| 5 | **Granite 4.2 8B** | Compact Apache 2.0 model with structured tool calling | More enterprise/tool oriented than specialized scientific; evaluate local retrieval answers. |
| 6 | **OLMo 3.1 7B Think / Instruct** | High transparency makes failures easier to audit | Korean quality may trail multilingual leaders. |
| 7 | **Falcon-H1 7B** | Small hybrid architecture and official multilingual benchmark report | Falcon-specific terms and Korean quality need review. |
| 8 | **Aya Expanse or Aya Vision 8B** | Explicit 23-language coverage including Korean | Non-commercial license; do not deploy for commercial use without different terms. |

## How the models fit the product

The application should not be tied to one vendor. The code’s local LLM adapter accepts an Ollama model tag from configuration. Changing the selected model should not change the evidence rules, retrieval method, calculator, comparison code, or API contract.

| Component | Job in Lab Process RAG | Guardrail |
|---|---|---|
| Request router (Jev or a local typed-decision model) | Select among a fixed list of backend routes such as evidence search, experiment comparison, failure-analysis summary, or calculation | Router picks a route; application code executes it. It does not invent evidence or directly modify experiments. Hosted Jev sees only minimal routing information. |
| Retrieval embedder and reranker | Find and rank paper passages / similar experiment records | Search score is not proof. Preserve paper/page/experiment provenance. Keep FTS as fallback. |
| Answer LLM (shortlist above) | Explain retrieved text and structured results in Korean or English | Prompt only with retrieved excerpts; require typed claim status and IDs; reject missing or invented citation IDs; show linked excerpts. |
| PDF OCR/layout model (e.g. Docling pipeline or dedicated Falcon OCR) | Extract scanned text, tables, and page layouts | Store extraction method and page/region; OCR is a proposed transcription, not a confirmed experimental fact. |
| Structured extraction model | Draft process variables, units, outcomes, and notes from papers | Never silently write to experiment records; require a quoted source span and user review. |
| Deterministic calculator | Calculate masses, dilution, amounts, ratios and units | No LLM arithmetic. Keep the numeric service authoritative. |
| Bayesian optimizer (e.g. BayBE) | Propose next experiment after variables, objectives, constraints, and real outcome data are defined | Not a general chatbot or cause finder. Disable for synthetic demo records; expose assumptions and constraints. |
| Evidence claim validator | Enforce `SUPPORTED` / `INFERRED` have citations and every citation exists in the retrieved set | UNKNOWN without evidence is allowed. Citation existence still does not prove entailment; keep answers reviewable and evaluate semantic support. |

Jev is an optional **decision router**, not a scientific judge and not a tool executor. That is a useful architectural role if request classification becomes unreliable, but there is no reason to make it part of the evidence chain. A fixed deterministic route map should remain the fallback.

## Performance: what the available evidence does and does not say

Vendor model cards publish useful task scores, but evaluation prompts, sampling, quantization, test contamination, and tool setup differ. Scores printed by different vendors are not a fair ranking. The Apple M5 and Ollama material helps establish runtime feasibility and memory behavior, not answer correctness. The latter grows with context and concurrent requests. A generated claim can cite a real retrieved passage and still misrepresent it, so a model benchmark cannot replace claim-level checks.

The fair selection method for this app is a small, versioned Lab Process RAG benchmark: Korean and English questions over the same uploaded PDFs and experiment records, including questions that must return UNKNOWN. Compare each candidate on answer support, citation-ID/page correctness, unsupported-cause rate, numeric fabrication, route/tool behavior, latency, peak memory, and model cold-start time. Keep vendor-reported scores clearly labeled as vendor-reported.

## Recommended integration path

1. Keep the default provider disabled and let the user select the exact model tag. Do not download a multi-GB model until the user selects a candidate.
2. Use one local generation adapter with bounded context, output length, evidence count, and concurrency. Model/runtime swaps should be configuration changes where possible.
3. Add an answer panel that displays status, model readiness, claim labels, and the cited evidence passages. If retrieval finds no passage, return UNKNOWN without calling a model.
4. Compare the shortlist against the project’s own labeled queries before recommending a winner.
5. Add embeddings/reranking, OCR, Jev routing, and BayBE as separate modules only when each has a defined evaluation set and a clear place in the workflow.
