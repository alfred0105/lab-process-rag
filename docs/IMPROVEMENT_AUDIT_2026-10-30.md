# Lab Process RAG 개선 점검 기록

점검일: 2026-10-30
검토 범위: 현재 저장소 코드와 로컬 SQLite DB. 기존 DB는 수정하지 않고 SQLite backup API로 사전 백업을 만들었다.

## 이번 단계에서 확인하고 수정한 문제

### 실험 비교

- 기존 비교 키가 변수 이름뿐이라 서로 다른 공정 단계의 같은 이름 조건이 덮어써질 수 있었다.
- 값과 단위를 문자열 그대로 비교하여 `1 h`와 `60 min` 같은 동등한 값이 다르게 보일 수 있었다.
- 변수 값의 종류와 결측 여부가 명확히 분리되지 않았다.
- 비교 키에 공정 단계의 순서·유형·이름, 조건 이름, 재료 문맥을 반영했다. 같은 조건의 반복 입력은 별도 항목으로 남긴다.
- `pint`로 호환 단위를 표준 단위로 바꿔 비교한다. 모르는 단위, 차원이 다른 단위, 한쪽에만 단위가 있는 값, 값 누락, 자료형 충돌은 차이라고 단정하지 않고 `unresolved_variables`에 기록한다.
- 허용 오차와 측정 불확도 필드는 현재 원본 데이터 모델에 충분히 없으므로 임의의 실험적 오차를 만들지 않는다. 이 한계는 비교 응답의 문맥에 표시한다.

### PDF와 근거 저장

- 기존 PDF ingestion 서비스가 내부에서 `commit()`하여 API 처리 뒤쪽의 실패가 전체 업로드를 되돌리지 못할 수 있었다.
- ingestion 서비스가 commit하지 않고 flush까지만 하게 바꿨다. Paper, EvidenceChunk, PaperSummary, 연구 주제 연결은 API가 소유한 단일 트랜잭션으로 처리한다.
- 빈 파일, 50 MiB 초과 파일, 500쪽 초과 PDF, 암호화 PDF, 파일명 경로 조작을 거부한다. 업로드 파일 크기는 최대치 + 1 바이트만 읽는다.
- PyMuPDF 문서는 context manager 안에서 닫는다.

### DB 참조 무결성

- SQLite는 새 연결에서 외래 키 검사를 기본으로 끄기 때문에 SQLAlchemy 엔진 연결 시 `PRAGMA foreign_keys=ON`을 설정했다.
- 현재 DB 백업과 원본 모두 `integrity_check`를 통과했고, 기존 레코드의 `foreign_key_check` 위반은 0건이었다.

### OpenFOAM 상태 점검

- 상태 API는 실행기가 쓰는 `simpleRushtonMRF` 대신 과거 경로의 `mixerVessel2DMRF` 로그를 확인해 설치 상태와 “튜토리얼 완료”를 혼동했다.
- OpenFOAM 설치 여부와 실제 실행 템플릿 디렉터리 존재 여부를 분리한다. 템플릿이 있다는 사실은 solver 실행 완료나 물리적 정확성으로 표시하지 않는다.
- 기존 프런트엔드 상태 키는 호환을 위해 남겼고, 새 `openfoam_template_available` 필드를 추가했다.

## 검증

- 기준선: 57개 테스트 통과.
- 수정 후 전체 백엔드 테스트: 65개 통과.
- 프런트엔드 TypeScript 검사 및 production build: 성공.
- 새 회귀 테스트는 같은 이름 조건이 여러 단계에 있을 때의 보존, 시간 단위 환산, 차원이 다른 단위 거부, 결측값과 0 구분, PDF rollback·업로드 제한, SQLite 외래 키 강제, OpenFOAM 템플릿 경로 확인을 포함한다.

## 다음 단계와 미구현 범위

이번 커밋 후보는 확인된 Phase 1 결함의 제한된 수정이다. 아래 목표는 아직 구현 완료가 아니다.

1. `routes.py`를 도메인별 API 모듈로 분할하고 `llm.py` 책임을 provider·router·tool selector로 분리한다.
2. ad-hoc DB 보정 코드를 버전 관리 마이그레이션으로 전환하고 복구 테스트를 추가한다.
3. 정규화된 분석/학습 데이터 계층, 불확도, 파일 해시, 측정 검토·승인 이력을 설계하고 실제 데이터 이전 경로를 만든다.
4. RAG 검색 품질 평가, 표·스캔 PDF 검증, 근거 내용 적합성 평가를 별도 검증한다.
5. XRD 피팅 및 상 후보 평가, SEM/TEM 객체 측정, AFM 지표에 기준 데이터와 알고리즘 버전·불확도 검증을 추가한다.
6. OpenFOAM 메쉬·수렴 검사 및 장시간 작업을 위한 영속 worker/queue를 구현하고 실제 VM 실행 결과로 확인한다.
7. Tool Registry, 실험 최적화/Bayesian Optimization, 폐루프 검증을 구현하되 측정 데이터·시뮬레이션·추론의 출처를 계속 분리한다.
8. 독립 학습된 JEV Decision Head, 공유 Transformer, Early Exit은 현재 구현돼 있지 않다. 현재의 후보 토큰 점수 방식과 다른 시스템으로 취급하고, 라벨 데이터·학습·오프라인 평가 계획을 먼저 마련해야 한다.

현재 JEV 관련 구조를 “학습된 JEV Head”라고 부르지 않는다. 이 점검에서는 자율 실험이나 실제 장비 제어를 수행하지 않았다.
