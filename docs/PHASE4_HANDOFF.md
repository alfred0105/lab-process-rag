## Phase 4 MVP implementation snapshot — 2026-10-31

The first executable GP/BO software MVP is implemented at commit `bf7de3541ccc4db0fda4977d3a70e90b4f195fbf` and passed GitHub Actions [run 41169550349](https://github.com/alfred0105/lab-process-rag/actions/runs/41169550349):

- `backend/app/services/optimization/gpbo.py`: RBF and Matérn GP, likelihood-based length-scale/signal/noise fitting, normalized inputs/target, Cholesky with jitter, predictive mean/std, serialized JSON parameters, EI/PI/UCB, and Branin sandbox benchmark.
- `backend/app/api/optimization.py`: strict accepted-data Dataset Builder, model train/read/predict/recommend, persistent candidate results, and a separate sandbox benchmark endpoint. Research mode joins only non-demo experiments with accepted LAB_RECORD inputs and accepted LAB_RESULT/ANALYSIS_OUTPUT outcomes within the selected topic and Method Version. Mixed normalized units are rejected. Measurement uncertainty is passed as per-observation variance when available. No approved pairs yields `INSUFFICIENT_APPROVED_DATA`.
- `backend/migrations/versions/0008_gpbo_mvp.py`: additive model/recommendation history tables. Saved models use JSON coefficients, never pickle. Recommendation records remain `PENDING_RESEARCHER_REVIEW`.
- `frontend/src/components/OptimizationPanel.tsx`: separate sandbox/research modes, user-supplied research parameter IDs and bounds, kernel prediction summary, uncertainty, ranked candidates, acquisition score, and an explicit human-review-only message.

Model diagnostic metrics use a deterministic 80/20 holdout: input and target normalization are fitted only on the training split; RMSE, MAE, negative log predictive density and 95% interval coverage are calculated on holdout rows. Because research datasets may be small, this is only a preliminary validation estimate. It is not external scientific validation.

The repeatable five-seed Branin report is [`backend/reports/phase4_branin_benchmark.json`](../backend/reports/phase4_branin_benchmark.json), regenerated by [`backend/scripts/benchmark_phase4_branin.py`](../backend/scripts/benchmark_phase4_branin.py). Each policy uses the same five-point seed-specific initial design and 20 additional evaluations. Median best objective over five seeds: Random Search **6.9162**, Latin Hypercube **1.6154**, GP-EI **0.4132**, GP-UCB **0.4647**; mean best values are 6.1098, 1.5976, 0.4097, and 0.4712 respectively. The known Branin minimum is approximately **0.3979**. The five-seed comparison took **0.92 seconds** on the recorded local macOS 27.0.1 arm64 / Python 3.12.14 environment. In this small synthetic comparison, EI performed best and all five GP-EI runs ended between about 0.3979 and 0.4214. This is evidence that the implementation path works on Branin only; it does not establish real-material optimization quality or broad optimizer superiority.

Verification on that commit: backend **182 tests passed**, frontend production build passed, browser E2E **3 passed**, and all GitHub Actions backend/frontend/browser jobs passed. The MVP gate is therefore `PHASE_4_MVP_IMPLEMENTED`; Phase 4 overall remains `IN_PROGRESS`. Research data is not yet available, so Research-mode predictions have not been validated against actual experiments. Category/multi-objective/noisy constraints, async durable Worker execution for larger jobs, authentication, richer parameter selection UI and multiple scientific domain benchmarks remain follow-up work. The initial GP/BO calls run synchronously; do not use this MVP for long-running high-dimensional jobs.

## 목표 구현 범위

- 승인된 실험 데이터의 optimization-ready contract와 실측/source/review 필터
- feature engineering, 물리 단위 정규화, 변수 bounds 및 물리 제약
- Gaussian Process regression, kernel 후보 선택, hyperparameter 최적화와 predictive uncertainty
- Bayesian acquisition: Expected Improvement, Probability of Improvement, Upper Confidence Bound
- constraint-aware/noise-aware optimization, replicate 및 다목적/Pareto 지원
- baseline 비교, grouped/campaign-aware cross-validation, leakage 방지와 surrogate validation
- 다음 실험 후보 ranking, 불확도 높은 구간 abstention 및 필수 입력 요청

Phase 4는 합성·공개 benchmark로 엔진 동작을 검증할 수 있지만, 실제 연구 최적화 성능은 승인된 실측 데이터와 사전에 정한 목표/제약 평가 없이는 VERIFIED로 처리하지 않는다.

## 필수 데이터 보호

- `source_type`은 실제 승인된 `LAB_RESULT`만 학습 허용한다. `LITERATURE`, `SIMULATION`, `SYNTHETIC_DEMO`, 모델 추론값은 보류/제외한다.
- `review_status`가 `APPROVED`가 아니거나 필수 provenance·단위·검토 계보가 없으면 학습을 시작하지 않는다.
- 서로 다른 topic, material identity, method version 또는 process step은 자동으로 한 집단에 합치지 않는다.
- 반복 측정 ID와 불확도를 유지한다. 불확도나 측정값을 추측해 채우지 않는다.
- 값은 물리 차원이 호환될 때만 명시적으로 정규화한다. pH/SI처럼 로그·모델 척도인 값은 일반 농도처럼 변환하지 않는다.
- 승인 가능한 데이터가 부족하면 최적화를 보류하고 부족한 필드와 승인 기준을 알려준다.

현재 저장소에는 이 문서가 설명하는 최적화 실행 및 실험-시뮬레이션 오차 보정이 완성되지 않았다. 본 문서는 Phase 4 구현자의 입력 계약이며 성능·과학 검증 증거가 아니다.
